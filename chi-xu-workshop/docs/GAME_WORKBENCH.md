# 工坊游戏工作台与方案试验

本轮借鉴用户提供的 Foldit 参考中的“围绕模型持续操作、即时反馈、保存与改进方案”循环。保留齿序工坊的材质与色调，不复制 Foldit 的蛋白质、生物能量或科研结果机制。

## 当前可玩循环

1. 首页仍选“观察挑战 · 短任务”，进入占满浏览器视口的真实 3D 工坊；可点“全屏”进入浏览器全屏。任务、方案、回放各为一个可收起的面板，不再向下翻网页才能操作。
2. 新任务通过原有观察判断，再选择任务牙留下操作判断。原九张短任务、三批 28 颗、位置与方向的独立调整和逐牙核对保持原样。
3. 直接拖动真实位置手柄或旋转环，也可长按正反按钮；画面右上实时显示当前任务的参考匹配指数及位置、方向误差。拖动中是预览，松手才保存。Esc 恢复已保存位姿。
4. 点“方案”→“保存当前尝试”。可以继续调整、撤销、走另一条操作路径，再只读查看旧方案，或“恢复继续”。恢复本身可撤销，并写入操作回放。
5. 自动保留各任务参考匹配指数最高的一次尝试，手动保留最近 12 份尝试。旧任务的尝试可查看，恢复仅限当前任务，不回写前批或越关。
6. “回放”打开独立时间轴面板。查看方案、原始/参考对比、回放与滑帘均不写实际病例位姿，不增加已核对数量。

工具快捷键：G 挪位置、R 转方向、1/2/3 选择世界 X/Y/Z、F 放大选中牙、按住 H 查看参考、Esc 取消拖动。输入答案或操作表单时不截获这些键。手机保留触摸手柄与按钮；视口变窄时适配整体牙模的观察距离。

## 指数的明确含义

- 对当前任务的 3—4 颗牙计算枢轴位姿平移误差的 RMS（u）和四元数角差的 RMS（度）。不是顶点距离、接触、咬合或生物能量。
- 记原始状态两项 RMS 为 P0、R0，当前为 P、R。尺度分别取 max(P0, 0.075u)、max(R0, 0.6°)，当前合计差距为 P/尺度P + R/尺度R；相对于原始合计差距的减少比例转换为 0—100，超出区间截断。原始合计为零时直接以尺度为基准惩罚新增误差。
- 只在指数显示中将小于 1e-5° 的浮点角差视为零，处理相同四元数的数值噪声，不改过关参数。
- 指数不能代替核对。位置与方向仍需同时达到既有挑战条件，逐颗核对后明确记录上传参考的精确终点。
- “个人最佳”仅指本机当前任务参考指数最高的尝试；不代表最佳治疗方案，也不比较不同玩家或不同病例的医疗效果。

## 保存与恢复边界

- 原挑战进度仍为 `chi-xu-workshop:reference-challenge:v2`，结构与旧记录不迁移；方案单独使用当前进度键加 `:attempts`。独立重试也有自己的方案键，不覆盖正式进度。
- 方案按参考 ID 和当前任务绑定，只保存本任务的牙位姿、核对与判断。恢复后其他任务牙完全保持当前已保存状态；当前任务的核对状态恢复到该方案时刻。
- 恢复候选先验证和保存，再应用，失败则保留原进度。方案写入失败不回滚已成功保存的病例动作；HUD 与方案面板显示失败。
- 损坏或版本不兼容的方案原文保留，禁用覆盖，病例仍能继续。导出记录包含方案及无法解析的原文，供排查。
- 没有自动求解、自动挪到参考、联网排行榜或向外发送数据。

## 本轮边界与验证

本轮实现沉浸式操作界面、参考反馈与方案试验循环；目标仍是同一份模型预测参考。真实邻牙约束、可靠穿透/咬合判定、多解物理评分和科研采纳流程尚未实现，不能把当前版本称为 Foldit 深度的开放科研求解游戏。

运行 `npm test`、`npm run build`；相关浏览器验证覆盖新工作台、方案保存/查看/恢复/撤销/刷新、坏方案原文保留、手机布局、原有观察与长按、真实拖动与模拟触摸、九任务 28 颗连续终点。截图 `screenshots/game-shell-desktop.png`、`game-shell-plans.png`、`game-shell-mobile.png` 为实际运行画面。Linux 软件 WebGL 测试不代表 Windows 原生性能与手机实机手感验收。
