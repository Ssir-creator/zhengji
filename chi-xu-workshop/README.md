# 齿序工坊 · Chi Xu Workshop

依据 48 页《齿序工坊_Claude完整阅读版.pdf》实现的独立浏览器 3D 正畸教学游戏开发版。**现已接入用户上传的 28 个真实 STL，可直接进入三关和自由练习。** 不修改或依赖原科研网站，不需要模型推理后端。

真实资产已经取得，但单位、上下颌、FDI、真实邻接、数据使用范围和教学目标尚未经过项目方/教师审核；当前是 PRD 原型位姿练习，不能称临床教学审核或全部 P0 验收已完成。

## 新增观察挑战

首页主入口 **“观察挑战 · 短任务”**：每次 3—4 颗，同一病例分三批、九张任务卡连续保存全部 28 颗。先做视角侦探或 A/B 找不同，再分别拖动位置手柄、旋转环或长按微调；逐牙核对、自评后继续。可按住查看参考、使用前后滑帘、双牙对照与只读操作时间轴；另开练习保留正式进度。完整操作及保存边界见 [观察挑战说明](docs/OBSERVATION_CHALLENGE.md)。

## 上传预测结果后的参考排齐

首页保留 **“参考排齐 · 28 颗（引导）”** 入口。使用用户上传 `results.zip` 的全部 28 个刚体变换，从原始牙位开始，按文件编号分成 9、9、10 颗三批连续调整。每批都明确显示全病例剩余数量，最终逐颗核对全部 28 颗达到预测参考，不能只移动两颗就当整副牙齿排齐。可用按钮逐步移动、撤销、放大观察和切换只读前后对比；原调整滑杆已移除，进度条只读。分别练习位置与方向请进入“观察挑战 · 短任务”。

28 个预测模型均已核对与原始 STL 的顶点、三角面及变换相符，牙齿形状不改。预测参考不代表临床审核结果或真实治疗过程。旧版操作练习、原参数、自由练习和旧存档独立保留；新参考练习另存进度，不覆盖旧记录。数据来源、核验方法与范围见 [预测参考接入说明](docs/PREDICTION_REFERENCE.md)。

## 旧版操作练习的界面

选中牙旁显示投影箭头或旋转弧线，画面内可直接点击“向左挪 / 向右上挪 / 顺时针转”等方向按钮，名称随观察角度变化；蓝色轮廓表示选中牙的目标，操作后立即反馈更近或更远。误差、坐标与测量移入“查看细节”。三关规则、牙模与存档格式不改，旧进度可以继续。详见 [方向操作与自动更新](docs/MOTION_AND_STARTUP.md)。

## 启动

Windows 推荐安装 Node.js 24 LTS。打开工程目录后：

- 双击 `开始游戏.cmd`：解压版在启动前自动检查并安装新版，没有变化时无需下载；联网更新失败会尝试打开本地版本。首次自动安装依赖，自动创建桌面入口，再打开浏览器。保留终端窗口，关闭窗口即停止服务。Git 开发工作区不自动改动代码。
- 双击 `创建桌面快捷方式.cmd`：在桌面创建游戏和更新入口。移动工程后重新创建快捷方式。
- 双击 `更新游戏.cmd`：解压版无需 Git，自动检查版本、下载、安装依赖和构建，再更新原目录并完整备份旧文件。最新版会直接提示无需下载。Git 克隆版仍只快进更新开发分支，有本地修改或分叉时停止。更新前先关闭游戏启动窗口。

启动固定使用 `http://127.0.0.1:5173`。进度保存在浏览器里：使用同一浏览器配置及同一地址；曾在 `localhost:5173` 游玩的玩家需继续使用该地址，两个主机名的存档互不共享。更新不会清理浏览器存档；换电脑、浏览器或端口前请先导出记录。端口占用时先关闭旧游戏进程，不自动换端口。ZIP 解压版也支持一键更新，无需反复手动下载与解压。首次给旧版本安装更新器的方法见 [Windows 一键更新](docs/WINDOWS_UPDATES.md)。

开发环境：

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

云端工作目录：`/workspace/zhengji/chi-xu-workshop`，依赖安装使用 `npm ci --cache /workspace/.npm-cache`。

首页直接渲染内置真实病例，可拖动旋转和缩放；首页预览不写挑战存档。工作台与首页共用实际 Three.js 场景，不使用概念图作为运行画面。牙模、病例清单、三关参数和进度格式保持原样。

**不需要每次重新导入牙模。** “开始新的挑战”“继续进度”“进入自由练习”会自动校验并加载随工程附带的真实病例。新挑战覆盖旧进度前会明确确认。模型和记录保留在本机，不建立远程遥测。

## 原始病例与显示资源

原文件编号是 `2–15、18–31`，共 28 个；直接沿用文件名作为模型 ID，**不把文件排序变成新牙位，不转换为 FDI**。

- 原始 STL：342,095 个三角面，`public/cases/initial/original/`。
- 标准 LOD：167,983 个三角面，约 4.12MB GLB。
- 低性能 LOD：83,983 个三角面，约 2.11MB GLB，启用时按需加载。
- 采样：每牙 256 个原始三角形重心，约 0.43MB。测距不用 LOD，也不用牙中心距离。
- 原始坐标、模型单位 u、未知 FDI=null、上下颌 unknown。无已确认邻接表时测距为未计算；穿透检查仍未实现。

见 [真实资产接入与制作记录](docs/REAL_ASSET_INTEGRATION.md)、[网格检查数据](docs/asset-inspection.json)、[LOD 报告](docs/lod-report.json)。

当前坐标视图按钮明确标注 +Z / −X / −Y，仅用于观察；不宣称解剖方向已审核。上下颌筛选未确认时禁用，不凭几何或数字猜测分组。

## 参数与数据

第一关模型 3/5 的目标 X 为 +1.50u/−1.50u；第二关模型 4 回原始参考位姿；第三关 3/5 的目标 X 为 +1.00u/−1.00u，6 回参考，7 固定。初始状态同时设置模型 4 的 Y +4u/Z +18° 与模型 6 的 Y −1.5u/Z −6°，确保以后每关完整继承上一关快照，不在转关时额外叠加扰动。

位置/朝向通关容差 0.35u/3°；固定漂移容差 0.00001u/0.001°。默认微调 0.25u/2°，精细选项 0.05u/0.5°。这些是软件参数，不是临床标准。

默认最少轴配置依据原型位姿任务建立；全部自由度与数值边界仍须教学审核。原始位姿不称为临床理想排牙。

进度使用 `chi-xu-workshop:challenge:v1`，与完整病例清单指纹及版本绑定。版本不兼容时保留旧原文供导出。自由练习不写入挑战键；回放只插值临时显示。原始 STL 不改写。

制作内置 GLB（Node.js 24）：

```sh
node scripts/prepare-case.mjs --source public/cases/initial/original --out public/cases/initial
```

该步骤可重建显示派生资源；绝不更改原始文件或按概念图重造牙齿。没有共享的原型源码或原科研网站源码，本工程为独立实现。

## 操作教学与本机检查

首次进入可依次试选牙、移动一次、撤销一次；过关后可查看本关前后对比、实际位移与转角以及学习反馈。编号现在位于牙列外侧，用细引线连接；旧进度和真实网格保持原样。

更新后关闭旧启动窗口，双击 `检查游戏.cmd`，会启动实际游戏并打开浏览器验收页，结果保存在 `本机检查结果.local.json`。检查期间会刷新桌面启动/更新入口；结束后双击 `开始游戏.cmd` 继续。只有你电脑实际运行后的报告才能确认 Windows 本机状态。详见 [本轮功能和验收记录](docs/LEARNING_AND_CHECKS.md)。
